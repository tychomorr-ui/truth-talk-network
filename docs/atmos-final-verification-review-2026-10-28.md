That note conflicts with the archive's later 11-node endpoint list and served identity, which identify `tesseract.nexinus.net` as **Tesseract Mirror**. Retain the earlier address as history; do not silently merge the two assignments.

I independently reproduced the public verifier's canonicalization rule and signature operations using Node's built-in Ed25519 verification [2] [3], then performed read-only HTTPS GETs to the 11 canonical endpoints listed in the repository README [1]. All 11 archived manifests have valid Ed25519 signatures and matching canonical payload hashes. All 11 current identity endpoints returned HTTP 200 without redirects; each served identity signature verified, and its canonical JSON exactly matched the corresponding archived manifest. All 11 health responses returned HTTP 200 without redirects; their Ed25519 signatures verified, `manifestCid` referenced the signed manifest payload, and `codeHash` matched the artifact hash in that signed manifest. The current identity and health response-body digests also matched the digests in all 11 archived observations. The served public-key fingerprints matched the public pin values.

These checks establish cryptographic consistency under the embedded node keys and match the current public pin values. They do not independently establish who controls those keys: the inspected GitHub commit and pin file are not signed by a separate trust root.

**ARCHANGEL is the exception to expected-pin consistency.** Its manifest signature, payload hash, public-key fingerprint, live identity signature, and health signature all verify. Its health `codeHash` matches the artifact hash in its own signed manifest. However, both its `manifestPayloadSha256` and `artifactSha256` differ from the values in the current public `expected-identity-hashes.json`. Thus the internally signed ARCHANGEL identity/health pair is coherent, but it does not match the current published expected-hash set. The archive's 11/11 report cannot be reproduced against that current file. This could reflect a stale pin file or a different local pin snapshot; the archive does not contain enough information to choose between them. Do not silently replace either value.

The current public expected-hash file says it was generated at `2026-10-28T17:41:00Z`, before the archived sync report [4]. GitHub identifies the inspected verifier `main` head as commit `102b84a2f37caa816a471d0d68c7552e6e8a860a`, authored at `17:43:39Z`; GitHub marks that commit unsigned [5]. ## Verification limits that remain

The published `atmos-sync-all.mjs` checks the local manifest signature, then tests the live identity's key fingerprint and `payloadHash`; it does not verify the live identity signature or compare the complete served document to the signed local manifest [3]. The independent check above did those extra checks successfully for this observation. The verifier also does not enforce the expected `manifestPayloadSha256` field or compare the signed manifest's `hashes.artifactSha256` against the expected artifact value [3] [4]. That gap is material for ARCHANGEL. It verifies a signed health claim against the expected artifact hash, but does not download or reproduce the application artifact bytes.

The signed health responses are cryptographically valid under their associated manifest keys, but not necessarily fresh. At the check time, ten `signedAt` values were approximately 24.6–25.1 hours old; ARCHANGEL's was about 66 minutes old. The published verifier does not enforce a freshness window, expiry, challenge, or anti-replay sequence [3]. Define those rules before using a signed health observation as present-tense evidence.

The archive and README distinguish eight identity-edge artifacts from three measured application files at KEIRA, VALKYRIE, and ARCHANGEL [1]. The eight identity-edge files are metadata artifacts, not application bundles. The three application hashes are attested in signed health, but their exact executable/bundle bytes are not included in the archive or independently reproducible from the public URLs checked here. The health responses expose local filesystem paths for those three nodes; previous safe GET checks at the corresponding URL paths did not retrieve bytes matching the advertised code hash. Replace those public paths with an opaque identifier or stable artifact URL, and provide reproducible build or measured-boot evidence if independent binary verification is required.

The archive README says WITNESS is a separate observer, not one of the 11 canonical nodes. It also claims a signed Cryptochrometer identity for WITNESS, but this archive's 11-node manifest and observation sets do not include a WITNESS verification record [1]. I did not independently verify that additional claim. Tesseract Mirror remains TESSERACT-A at `tesseract.nexinus.net`, distinct from Tesseract-Terminus at `terminus.nexinus.net` and the Tesseract-A Core verifier capability. Truth-Talk still has no live Rootgate identity handoff, Archangel receipt-import contract, Valkyrie API, or Pharo-Lapse peer route.

## Safe next corrections

Version and preserve the exact expected-hash file used for every verification run. Require the verifier to compare all four declared hash fields, verify the *served* identity signature and full canonical document, and reject a signed manifest whose artifact hash differs from the approved pin. Define health freshness and replay rules. Label `VERIFIED` as signed identity/health attestation unless the application bytes or a reproducible measurement are actually checked. Sign or otherwise authenticate the observation receipt and verifier release before importing either as cross-node provenance. Keep all Truth-Talk integrations operator-approved and versioned; this archive does not authorize a live connection to Rootgate, Archangel, or Valkyrie.
